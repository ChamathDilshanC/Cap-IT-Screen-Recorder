How to read this book

Every claim
is labelled.

This book describes a brand that already exists, and recommends how it could grow. The two are never mixed on the same line without a label.

EXISTING

Verified in the repository: the logo artwork, the shipped colour, type, spacing, radius and motion tokens, the screenshots, the README, the capture code. Values are parsed from source, not retyped.

DERIVED

Produced mechanically from existing artwork — a crop, a recolour, a plate behind the symbol. Nothing is redrawn.

PROPOSED

A recommendation, with its reasoning and measured contrast. Not applied to the application. Includes the Midnight / Arctic palettes and the horizontal lockup.

CONCEPT

An exploratory visual (marketing mock-ups, graphic-language studies). Illustrative, not a promise of a feature.

Source of truth

src/CapIT.Desktop/Styles/ (Colors, Tokens, Typography, Motion, Icons), assets/Logo-CapIT.png, docs/screenshots, README v3.13.1.

Screenshots

Brand overview

The recording should be easy.
The result should look intentional.

Cap-IT is a focused, GPU-assisted Windows screen recorder for polished tutorials, demos, bug reports and social clips. It keeps source selection, live preview, recording, audio monitoring, effects, annotations, editing and export in one native place.

Home — the real Arctic theme, v3.13.1.
Purpose

To remove the distance between doing something on screen and showing it well. People should spend their effort on what they are demonstrating, not on assembling the video.

Vision

Every tutorial, bug report and walkthrough made on Windows can be captured, refined and shared in a single sitting — without a second tool and without a result that looks accidental.

Mission

Build the most considered native recorder on Windows: precise capture, a camera that follows the action, and a review workspace that keeps the original safe.

Brand story

Made by someone who got tired of the tape and string.

Cap-IT began as a way to make tutorials without juggling a recorder, a zoom plug-in, a webcam tool, an annotation overlay and a video editor. Each release since has pulled one more of those into the same window: DXGI capture, a camera that eases toward the cursor, a floating controller that never appears in the recording, a library, a review workspace.

The result is deliberately a craft tool, not a platform: native, quick to open, quiet in use, and honest about what it does.

Theme behaviour

Switching themes must never touch a recording.

Theme is presentation state. In v3.13.1 it lives in AppSettings.Theme and App.ApplyTheme, which only sets Avalonia’s RequestedThemeVariant. The recording engine (CapIT.Infrastructure.Windows) contains no reference to theme at all — switching mid-recording only repaints brushes.

EXISTINGVerified

A search of the infrastructure project for “Theme” finds nothing. The floating recording controller is themed like any other window and is never part of the captured frame.

Manual & system
  • Options: System default · Light · Dark (existing).
  • “System default” follows the Windows app mode (existing).
  • Proposed: the toggle in the title bar shows the resolved theme, not the setting.
Persistence
  • Stored in settings.json beside other preferences (existing).
  • Applied before the first window is shown, to avoid a flash of the wrong theme.
  • The standalone editor (--review) reads the same preference.
Transitions
  • Proposed: 180 ms cross-fade of surfaces; none under reduced motion.
  • Never animate the live preview, meters or the REC indicator.
  • No re-initialisation of capture, audio or encode.
Correct variants

Icons use currentColor, so they follow the theme. The logo uses the stacked-reversed lockup on Midnight and the standard one on Arctic; the colour symbol is unchanged in both.

High-DPI

Strokes scale with icon size (existing). Hairlines are 1 px at 100 % and stay 1 device-independent px at 125–200 %; verified renders were produced at 125 % scaling.

Semantic colour

Components reference semantic tokens only. A component that needs a raw hex has found a missing token.

Two kinds of motion

Interface motion uses eased curves, ≤ 220 ms, and only transform and opacity. Camera motion lives in the recorded video: a critically damped spring on the crop rectangle, with no overshoot, using real elapsed time so it stays smooth when frames arrive unevenly.

Reduced motion

Move whole pixels at rest; allow sub-pixel translation only during the move. Never scale text up from below 1× — start at 1× and scale down.

Brand governance

Who owns what, and how it changes.

Ownership & versioning
  • Owner: the repository maintainer (ChamathDilshanC). Contributors propose; the owner approves.
  • Brand version: this book is 1.0 and uses semantic versioning: patch = fixes, minor = additions, major = identity change.
  • Product baseline: v3.13.1. Each release re-checks the screenshots and tokens.
  • Assets are named capit-<thing>-<variant>-<size> and are never edited in place — a new file gets a new variant name.
Approved logo versions

Existing: stacked lockup, symbol. Derived: reversed lockup, monochrome. Proposed (pending approval): horizontal lockup, app-icon plates.

Tokens

Source of truth is Styles/*.axaml for what ships and the two theme JSON files for what is proposed. build_tokens.py regenerates them and fails if contrast regresses.

Screenshots

Regenerate with the app’s snapshot harness (Debug, both themes) and a demo configuration whenever a page changes. Keep the previous version folder as an archive, as v3.6.0 is.

Release artwork

Use the templates; headline = product + version; one real screenshot; both themes where the channel allows a choice.

Change review & rules

Four steps to change the brand.

01
Propose

Open an issue with the reason, a before/after and the affected tokens or assets.

02
Measure

Run the token build; every pair must pass. Re-render the UI in both themes.

03
Review

Owner reviews in a pull request; recording code is reviewed separately from brand work.

04
Publish

Bump the brand version, update the book and assets, note it in the release.

Do
  • Use semantic tokens; add a token before adding a hex.
  • Show both themes whenever you show a component.
  • Label anything that is not shipped (proposed / concept).
  • Keep the original recording promise in every export flow.
Don’t
  • Redraw, recolour or re-proportion the logo.
  • Invert the dark palette to get a light one.
  • Claim performance, compatibility or features that are not verified.
  • Mix brand changes into recording-pipeline commits.

Provenance & limits

What this book is built on, and what it is not.

  • No vector master. The repository holds only PNG logo artwork; every variant is derived from it. Request the original vector files before print production.
  • Wordmark is tiny (2.4 % of the symbol height) — a horizontal lockup is proposed because of it.
  • Proposed ≠ shipped. The Midnight / Arctic palettes are recommendations; the application’s colours are unchanged.
  • Not verified: app support for reduced motion, screen readers and text scaling; light-theme focus visuals; non-Latin script rendering.
  • Recording pipeline untouched. The Smart Tracking work and its limits are in docs/SMART-TRACKING-RECORDING-FIX.md; audio tail, zoomed text sharpness and broader continuity tests remain a separate validation pass.
